# 版本、哈希与作者存证

## 为什么做

商业许可、侵权投诉、平台申诉、模型语料审计，都需要证明三件事：

1. 这个版本是作者的作品；
2. 这个版本在某个时间点已经存在；
3. 对方使用的版本与作者版本是否同一。

Git 提交历史、版本号、文件哈希和公开仓库时间戳，是低成本、可复核的证据链。

## 现有证据

- 各书库 `VERSION`、`CHANGELOG.md`、`CITATION.cff`；
- Git 提交历史与远程仓库（GitHub）；
- `LICENSING/PROVENANCE.json`：全系列文件哈希清单；
- 站点发布记录与页面 URL；
- 商业合同、发票、付款凭证、往来邮件。

## 生成方式

在 `runze-daokedao` 根目录运行：

```bash
python3 LICENSING/scripts/fingerprint.py
```

输出 `LICENSING/PROVENANCE.json`，包含：

- 生成时间；
- 每个书库的当前 commit、分支、远程；
- 文件数、总字节、聚合 SHA-256；
- 逐文件 SHA-256（可按需过滤）。

## 使用方式

- 对外许可时，把 `PROVENANCE.json` 与作品清单一并交付；
- 发现侵权时，对比对方文件哈希与作者哈希；
- 模型方要求“语料版本证明”时，提供 commit + hash + 公开 URL；
- 不把哈希说成“版权登记”；它只是技术存证。

## 更强存证（按需）

- 可信时间戳（TSA）；
- 公证处证据保全；
- 区块链存证；
- 中国版权保护中心作品登记。

商业许可金额较大、对方是上市公司或跨境主体时，建议至少做可信时间戳或公证。
